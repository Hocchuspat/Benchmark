# Benchmark

Локальное приложение с терминальными командами и настольным окном для подготовки
первичных досье компаний из Excel-выгрузки АСТРА.
Python читает Excel и хранит очередь, Codex CLI исследует одну компанию за запуск,
после чего Python проверяет карточку и сохраняет результат. Используется вход
в Codex через ChatGPT, без API-ключа и платных API.

## Запуск готового приложения без Python

**macOS (Apple Silicon), версия 1.0.1:** откройте `dist/1.0.1/Benchmark.app` двойным щелчком.
Можно перенести приложение в «Программы». Для передачи другому пользователю
используйте архив `dist/1.0.1/Benchmark-1.0.1-macOS-arm64.zip`: распаковать, перенести
`Benchmark.app` в «Программы», открыть.

**Windows x64:** архив версии 1.0.1 — `dist/1.0.1/Benchmark-1.0.1-Windows-amd64.zip`.
Распакуйте его на Windows и откройте
`Benchmark/Benchmark.exe`. Сохраняйте всю папку `Benchmark` вместе с её содержимым:
исполняемому файлу нужны лежащие рядом библиотеки и обработчик.

Внутри сборки уже находятся Python, Qt, Excel-библиотеки и официальный Codex CLI.
Отдельно устанавливать Python, Node.js или Codex, открывать терминал и вводить
команды не требуется. При первом запуске нажмите **«Войти через ChatGPT»**;
для обработки нужен интернет и доступ к Codex в аккаунте.
Если вход в Codex уже выполнен на компьютере, приложение использует его.
API-ключ не нужен и не принимается.

Существующий прогресс не входит в распространяемую сборку. Откройте своё
исследование кнопкой **«Открыть»** и выберите папку с `state.sqlite3`
(например, `runs/pilot` из каталога разработки). Ничего импортировать заново не нужно.
Результаты и исходный Excel не перемещаются при обновлении приложения.

По умолчанию новые исследования сохраняются в доступной пользователю папке:

- macOS: `~/Library/Application Support/Benchmark/runs/`;
- Windows: `%LOCALAPPDATA%\Benchmark\runs\`.

Можно выбрать другую папку при создании исследования. Размеры окна, тема и
параметры отображения сохраняются в пользовательских настройках ОС.

## Установка для разработчика

Нужны Python 3.11+ и установленный Codex CLI с командами `exec`, `--output-schema`,
`--json`, `--ephemeral`, `--ignore-user-config`. Проверено на Codex CLI 0.166.0.
Разработка и пилот выполняются из этого каталога: здесь находятся AGENTS.md и skills/.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[gui]"
python -m benchmark login
python -m benchmark doctor
```

Windows PowerShell: вместо `source` используйте `.venv\Scripts\Activate.ps1`.
Команды можно вызывать и как `benchmark ...` после установки.
Для работы только в терминале достаточно `python -m pip install -e .`.
Для удалённого терминала есть `python -m benchmark login --device-auth`.
Авторизация API-ключом отклоняется до обработки. Ключи не читаются, не сохраняются
и не передаются дочернему процессу. Пользовательская конфигурация провайдеров Codex
не загружается; явно запрашиваются провайдер OpenAI и вход ChatGPT.

## Настольное приложение

Основной интерфейс построен на Qt/PySide6. Графические зависимости входят в
дополнение `gui`; в уже созданном окружении их можно добавить той же командой
`python -m pip install -e ".[gui]"`. Затем откройте окно:

```bash
python -m benchmark gui
```

Можно сразу указать существующее исследование:

```bash
python -m benchmark gui --run-dir runs/pilot
```

При обычном запуске открывается пустой стартовый экран с кнопкой **«Загрузить Excel»**.
Предыдущая очередь автоматически не открывается, даже если сохранены старые настройки.
Чтобы увидеть этот экран, запускайте **без `--run-dir`**. Параметр `--run-dir runs/pilot`
означает явное открытие уже сохранённого исследования и сразу показывает его компании.
На стартовом экране можно также выбрать сохранённую папку кнопкой
**«Открыть сохранённое исследование»**. Новые исследования не запускаются автоматически;
вход в ChatGPT остаётся отдельной кнопкой сверху. API-ключ не нужен.

1. Для нового файла нажмите **«Загрузить Excel»** (или **«Новое исследование»** в открытой очереди), выберите `.xlsx`, лист
   (или автоматическое определение) и папку нового исследования, затем **«Создать очередь»**.
   Папка каждого исследования хранит свой прогресс независимо от остальных.
2. Для продолжения нажмите **«Открыть»** сверху и выберите папку,
   в которой находится `state.sqlite3`.
3. Если вход не выполнен, нажмите **«Войти через ChatGPT»** и завершите вход в браузере.
   Кнопка находится сверху; после входа она показывает **«Выйти из ChatGPT»**. Выход
   удаляет сохранённую авторизацию Codex CLI на этом компьютере и позволяет сменить аккаунт.
   Исследования остаются сохранёнными. Кнопка недоступна во время обработки.
4. Выберите число компаний из выпадающего списка (10, 20, 50, 100 или **«Вся очередь»**)
   либо введите своё число (по умолчанию **«Вся очередь»**; пустое поле или 0 — вся очередь), нажмите
   **«Начать обработку»** или **«Продолжить»**. Готовые карточки пропускаются.
   «Вся очередь» — подсказка пустого поля: просто нажмите в него и введите число.
   Число можно набрать или вставить в текстовое поле; стрелка справа открывает готовые
   варианты. Во время обработки поле остаётся доступным — изменение действует на следующий запуск.
5. Поиск работает по названию, ИНН и сайту. Фильтры: **«Все»**, **«Обрабатывается»**,
   **«Обработан»**, **«Не обработан»**. Выбор строки открывает сведения и источники справа.
   Ссылки на источники открываются в браузере. Замечаний в карточке нет.
   Значок копирования в колонке **«Сайт»** и поле сайта справа копирует URL в буфер обмена.
   Зелёная анимированная галочка подтверждает копирование, затем возвращается обычный значок.
   В начале карточки всегда видны **«Виды деятельности»** и **«Функции компании»**;
   если сведения отсутствуют, показано **«Нет данных»**.
   Для повторного исследования выберите компанию и нажмите **«Повторить»** в карточке
   справа. Будет обработана только она; предыдущая карточка и файлы попыток сохранятся,
   в том числе при ошибке нового запуска или достижении лимита. Повтор расходует подписку
   как обычное исследование и доступен после входа, когда другая обработка не идёт.
   При повторе локальный загрузчик пробует также найденный ранее сайт, даже если
   в исходном Excel адреса нет. Принадлежность сайта компании проверяется заново.
6. **«Остановить»** прерывает незавершённые задания и сохраняет готовые результаты.
   После завершения остановки доступна **«Продолжить»**: незавершённые компании
   исследуются заново, сохранённые карточки пропускаются. При закрытии окна
   выполняется такая же остановка, после чего окно закрывается.
   Кнопка продолжения доступна после завершения фонового процесса и сохранения отчёта.
   Сверху показано **«Время обработки»** в формате ЧЧ:ММ:СС. Это суммарное время
   запусков в текущем окне, без пауз; при открытии исследования счётчик начинается с нуля.
7. В меню **«Экспорт»** команда **«Открыть отчёт Excel»** пересобирает и открывает файл.
   **«Сохранить копию…»**
   сохраняет копию в выбранное место; заменить ею исходный Excel запрещено.

Рабочее пространство:

- Боковой панели и меню «Вид» нет. Вход через ChatGPT, открытие исследования,
  экспорт и создание исследования находятся сверху. Кнопка «Обновить» удалена.
- Строки компактные по умолчанию, в том числе после загрузки старых настроек.
- Карточка компании всегда справа; ширина таблицы и карточки меняется перетаскиванием.
- Счётчики показывают общее количество компаний, обработанные и необработанные.
- Иконка луны/солнца переключает тему; кнопка в таблице выбирает видимые колонки.
- Тема, размеры окна, панели и колонки сохраняются между запусками средствами ОС.

Горячие клавиши: Ctrl+F — поиск, Ctrl+O — открыть исследование, Ctrl+Shift+D — тема.
На macOS вместо Ctrl используется ⌘.

Обработка идёт в отдельном процессе через существующие терминальные команды.
Окно остаётся доступным во время поиска. Сообщения о состоянии и ошибках показываются
под индикатором прогресса. При входе в ChatGPT доступна кнопка открытия страницы входа,
если браузер не открылся автоматически. Исходные ответы и технические журналы попыток
сохраняются в каталоге исследования; отдельного экрана журнала в интерфейсе нет.

Для сравнения прежний интерфейс Tkinter доступен по отдельному флагу:

```bash
python -m benchmark gui --classic --run-dir runs/pilot
```

Для него нужен Tkinter. Основному интерфейсу Qt компонент Tkinter не требуется.
Окно и его сценарии проверены на macOS. На Windows x64 проверены сборка,
запуск окна, импорт Excel, сохранение карточки, продолжение и экспорт
с подставным исследователем. Живой пилот через Codex выполняется отдельно.

## Сборка приложения

Сборка выполняется отдельно на каждой ОС; PyInstaller упаковывает интерпретатор
вместе с кодом и зависимостями. Для разработчика рекомендуется Python 3.14.

```bash
python -m pip install -r requirements-build.txt
python scripts/build_app.py
```

Скрипт скачивает официальный Codex CLI **0.166.0** под архитектуру компьютера,
проверяет SHA-256 каждого архива по метаданным GitHub Release и добавляет
исполняемые файлы, LICENSE, NOTICE и манифест версии. Загрузка происходит
на этапе сборки; клиент получает готовые файлы. Версия фиксирована в
`scripts/fetch_codex.py`. Для повторной сборки без загрузки:

```bash
python scripts/build_app.py --codex-dir build/vendor/codex
```

Сборка первой версии в отдельную папку:

```bash
python scripts/build_app.py --codex-dir build/vendor/codex --dist-dir dist/1.0.1
```

Результат: `dist/Benchmark.app` и ZIP на macOS, `dist/Benchmark/Benchmark.exe`
и ZIP всей папки на Windows. macOS arm64 и Intel собираются на соответствующей
архитектуре. Нынешние зависимости Qt требуют macOS 14+; Windows — 64-битная сборка.
Локальная macOS-сборка имеет техническую ad-hoc подпись. Для публичного выпуска
потребуются Developer ID/notarization на macOS и отдельная подпись Windows;
сертификаты и ключи не включены в репозиторий или приложение.

В `.github/workflows/build-app.yml` настроена нативная сборка macOS и Windows:
запустите workflow **Build desktop application** в GitHub Actions (платформа `windows`
или `both`) или отправьте тег `v*`. Push в ветку `build/windows-*` запускает только Windows.
ZIP доступны в Artifacts завершённого запуска; публикация релиза автоматически
не выполняется. Проверки сборок используют тестовые данные и подставной CLI,
не расходуя подписку ChatGPT. Рядом с ZIP создаётся контрольная сумма SHA-256
и инструкция START.txt. Старые тестовые сборки не входят в версию 1.0.1.

Проверка готовой сборки:

```bash
python scripts/smoke_app.py dist/Benchmark.app
# Windows:
python scripts/smoke_app.py dist/Benchmark
```

Проверка запускает обработчик из сборки вне репозитория, с PATH без окружения
разработчика: импорт Excel, чтение состояния, экспорт, доступ к ресурсам,
`codex --version` и запуск интерфейса. Обработка одной компании и продолжение
проверяются с подставным исследователем: `/bin/sh` на macOS и отдельным тестовым
`.exe` на Windows. Компилятор .NET Framework нужен только сборочной Windows-машине
для создания этого тестового файла; в клиентскую сборку он не входит. Настоящее
исследование и расход подписки не запускаются. Живой пилот через Codex проводится отдельно.

Внутри приложения `Benchmark` отвечает за окно, `Benchmark-worker` — за фоновые
команды; оба используют встроенный Python и общие библиотеки. В Windows обработчик
и Codex запускаются без консольных окон. AGENTS.md, четыре скилла, JSON-схема,
иконки и лицензии упаковываются вместе с программой; базы, Excel, учётные данные
и каталоги исследований в сборку не входят.

## Пилот

```bash
python -m benchmark init "/путь/к/Benchmark.xlsx" --run-dir runs/pilot
python -m benchmark run --run-dir runs/pilot --max-companies 10
python -m benchmark status --run-dir runs/pilot
```

В приложенном файле автоматически выбирается лист «Выборка компаний». Если несколько
листов подходят, импорт попросит указать `--sheet "Название листа"`. Для нестандартного
расположения заголовков есть `--header-row 3`. Поддерживается `.xlsx`; `.xls` нужно
предварительно пересохранить в `.xlsx`. Колонки сайтов распознаются по заголовкам,
включая «Электронная страница» и уточнённый адрес; читаются гиперссылки и HYPERLINK.
В очередь входят все строки с названием компании, независимо от старых отметок отбора.

Повторный `init` в ту же очередь запрещён. Изменения исходного файла не меняют уже
созданную очередь. Для нового набора используйте другой каталог. Импорт запоминает
SHA-256 файла, имя листа и строку каждой компании. При необходимости ограничить
сам импорт используйте `init ... --limit 20`.

`--max-companies` — число попыток за один запуск, по умолчанию 0 (вся очередь). Тайм-аут одной
компании — 420 секунд. Дополнительно доступны `--timeout 240`, `--model ИМЯ` и
`--token-budget 200000`. При заданном бюджете токенов используется один поток. Бюджет проверяется между компаниями, поэтому одна
компания может превысить порог; это не ограничение стоимости или лимита подписки.

Для повторного исследования одной компании используйте
`python -m benchmark run --run-dir runs/pilot --company-id ID_КОМПАНИИ`.
ID есть в отчёте. Этот режим не обрабатывает остальные компании и не удаляет
предыдущий результат. Флаг `--company-id` нельзя сочетать с `--retry-failed`.
При импорте, запуске и экспорте проверяется, что путь отчёта не совпадает с исходным
Excel, включая символические и жёсткие ссылки. При совпадении выберите другую папку исследования.

## Остановка и продолжение

```bash
# Во втором терминале: прервать незавершённые задания, сохранив готовые результаты.
python -m benchmark stop --run-dir runs/pilot

# Продолжить с необработанных; готовые карточки не запрашиваются заново.
python -m benchmark run --run-dir runs/pilot --max-companies 10

# Дополнительно вернуть ошибки обработки в очередь.
python -m benchmark run --run-dir runs/pilot --retry-failed --max-companies 10

# После проверки пилота — обработать оставшуюся очередь.
python -m benchmark run --run-dir runs/pilot --max-companies 0
```

Ctrl+C прерывает текущий процесс Codex и возвращает компанию в очередь. После аварийного
завершения состояние `running` восстанавливается при следующем запуске.
Если Codex успел записать полный ответ и событие завершения, но Python не успел
зафиксировать транзакцию, ответ проверяется и восстанавливается без нового запроса.
Лимит подписки
и ошибка авторизации возвращают текущую компанию в `pending` и останавливают обработку
с кодом 75. После восстановления доступа достаточно той же команды `run`. Тайм-ауты,
невалидные JSON и другие ошибки отмечаются `failed`; повтор — только с `--retry-failed`.
После трёх последовательных ошибок очередь останавливается для диагностики.
Одновременные обработчики одной очереди блокируются системной блокировкой.

## Результаты и проверка

В каталоге запуска:

- `state.sqlite3` — основной журнал и сохранённые карточки; транзакция после каждой компании.
- `attempts/<id>/<номер>/` — запрос, JSONL-события, stderr и исходный ответ каждой попытки.
- `reports/report.xlsx` — один лист «Досье компаний» и семь столбцов по ТЗ.
- `reports/report.csv`, `reports/sources.csv` — UTF-8 с BOM, разделитель `;`.
- `reports/pilot.json` — статусы, подтверждённые сайты, число источников и расход токенов.

Отчёты пересобираются в конце запуска, при лимите и при Ctrl+C. При жёстком завершении
процесса результаты уже находятся в SQLite; восстановите отчёт:

```bash
python -m benchmark export --run-dir runs/pilot

# Повторная локальная проверка сохранённых ответов и журналов, без расхода подписки.
python -m benchmark recheck --run-dir runs/pilot
```

Итоговые XLSX и CSV содержат ровно семь колонок: «Название компании», «ИНН»,
«Электронная страница», «Оквэд», «Продукция/Услуга», «Вид деятельности», «Функции».
В XLSX один лист «Досье компаний», без дополнительных листов, ID и статусов.
Все компании очереди остаются в отчёте; отсутствующие найденные сведения — пустые ячейки.
Исходный Excel не переписывается, формулы и финансовые показатели не переносятся.
Сведения об источниках доступны в карточке и техническом sources.csv.

В интерфейсе «Обработан» означает наличие сохранённой карточки; «Не обработан» — её отсутствие.
В приложении во время активного задания показывается синий статус **«Обрабатывается»**,
в том числе при повторе уже сохранённой компании. Фильтр с этим названием показывает
запущенные задания. После завершения статус автоматически возвращается к итоговому.

На листах Excel и в CSV нет замечаний, причин проверки, ошибок попыток и пояснений
к фактам. В карточке приложения две вкладки: сведения и источники. Проверки источников
и служебные сведения сохраняются внутри исследования для продолжения работы.

Поиск деятельности и функций продолжается и без официального сайта: используются
открытые страницы по тому же ИНН, реестры лицензий и сведения о работах/контрактах.
Заявленные виды по ОКВЭД и разрешённые лицензией функции можно сохранить с явной
оговоркой в тексте; они не подтверждают фактическое выполнение работ. Эти ограничения
остаются в технических файлах; в самих описаниях сохраняется фактическое основание утверждений.
Ориентир исследования —
до 8 запросов и до 12 открытий на компанию, без повторов одинаковой выдачи.

После обновления правил сохранённые карточки сами не исследуются заново.
Команда `recheck` может вернуть источники, ранее ошибочно исключённые из смешанных
вызовов поиска и открытия, но не дописывает отсутствовавшие в исходном ответе факты.
Она также пересчитывает внутренние проверки без запросов к модели,
предварительно сохранив резервную копию. Новые ответы содержат `report_issues`
с конкретными нерешёнными проблемами отчёта; прочие `warnings` остаются техническими данными и не выводятся в приложении и отчёте.
Сохранённые ответы прежней схемы без `report_issues` остаются совместимыми.
Чтобы собрать новые сведения, выберите нужную компанию и нажмите «Повторить»;
это один новый запрос исследования с расходом лимита подписки.

Перед исследованием Python загружает исходный и уточнённый сайты с компьютера
пользователя. Сначала выполняются обычные HTTP-запросы, проверяются варианты с `www`
и без него, HTTPS и публичная HTTP-версия. Если получены ошибки доступа/тайм-аут
или вместо сведений вернулась оболочка, требующая JavaScript, включается резервная
загрузка через **Qt WebEngine / Chromium** в отдельном процессе. Браузер выполняет
JavaScript и читает видимый текст, затем разделы с реквизитами, контактами и деятельностью.
Повторно открывать уже прочитанную страницу другим вариантом домена не требуется.

Оба способа делят общий бюджет до 40 секунд, 12 загрузок страниц и 8 сохранённых страниц
на компанию. Часть бюджета резервируется для браузера. Ошибка или зависание движка
не прерывает очередь: сохраняются уже прочитанные источники, агент продолжает поиск.
Проверка TLS остаётся включённой; явный запрет доступа, CAPTCHA и авторизация
не преодолеваются автоматически. Используется временный профиль без личных cookies,
с запретом форм, скачиваний, доступа к локальным ресурсам и разрешений сайта.

Для запуска из исходников движок устанавливается вместе с `.[gui]` или
`requirements-gui.txt`. Начиная с PySide6 6.12 это отдельный пакет `PySide6-WebEngine`.
Конфигурация следующей клиентской сборки включает движок и его служебные ресурсы;
устанавливать отдельный Chrome клиенту не потребуется. Новая сборка пока не выпускалась.
В терминальной установке без движка HTTP и веб-инструменты Codex продолжают работать.

В `attempts/<company_id>/<number>/` сохраняются `local-web.json`, HTML или DOM после
выполнения JavaScript и извлечённый текст в `pages/`. Журнал содержит способ загрузки,
фактические адреса, даты, ошибки попыток и SHA-256 копий. Для браузера отдельно
фиксируется успешное завершение загрузки; неизвестный HTTP-код не подменяется кодом 200.
Текст передаётся агенту как недоверенные данные и сверяется с сохранёнными копиями
при повторной локальной проверке, без открытия сайта заново.

Локальная проверка контролирует схему, ID компании, форматы реквизитов, даты, ссылки
фактов на источники и согласованность ИНН. Она **не доказывает правдивость источника**.
Дополнительно каждая ссылка сверяется с журналом веб-вызовов и сохранёнными копиями
локального загрузчика. Для локальной копии проверяются наличие файлов и контрольные
суммы; один URL или ответ с ошибкой доказательством не считается. Если осталась только
поисковая выдача без прочитанной страницы, такой источник исключается. Факты, у которых
после этого не осталось источников, заменяются на null, а результат проверки сохраняется в технических файлах.
Полный первоначальный ответ сохраняется в каталоге попытки. Неизвестный формат журнала
не трактуется как доказательство открытия. Проверено на событиях Codex CLI 0.166.0.
При конфликте ИНН сведения с чужого официального сайта исключаются из фактов исходной
компании. Деятельность и функции не переносятся с неподтверждённого сайта. Источники
конфликта сохраняются для проверки; их наличие не делает чужую деятельность фактом.
Необходимо отдельно проверить пилот: принадлежность каждого сайта; соответствие
описаний конкретному юрлицу; подтверждение заполненных фактов открытыми страницами;
корректность функций и отсутствие рекламного текста. Формулировки 2–5 предложений
дополнительно проверяются эвристикой. Счётчики токенов — данные CLI, а не остаток
подписки в процентах. При неизвестном расходе/остатке не выводится выдуманное число.
`attempts_without_usage` показывает попытки, для которых CLI не прислал счётчик расхода.

Экспорт создаётся через временные файлы с атомарной заменой. При открытом в Excel
выходном файле на Windows замена может не пройти: закройте файл и выполните `export`.
Сама база с результатами при этом сохранена. Для резервной копии при остановленном
обработчике копируйте весь каталог запуска, включая возможные SQLite WAL-файлы.

## Правила и навыки

Общие требования — в [AGENTS.md](AGENTS.md). Четыре навыка расположены в `skills/`:
поиск сайта, сбор фактов, анализ деятельности, контроль качества. Обработчик включает
их содержимое в каждый запрос, поэтому результат не зависит от автоматического
обнаружения навыков в конкретной установке Codex. Схема карточки находится в
`benchmark/resources/company.schema.json`. Новые правила вступают в силу для новых
попыток; текст запроса каждой выполненной попытки сохраняется для воспроизводимости.

## Проверки разработки

```bash
python -m unittest discover -s tests -v
```

Тесты используют подставной CLI и не расходуют подписку. Проверяются импорт,
гиперссылки, совпадение ID, источники и ИНН, повторный запуск, авария/прерывание,
лимит, авторизация, тайм-аут, защита от формул Excel, блокировка и экспорт.
Проверки фонового процесса, чтения прогресса и интерфейса Qt входят в обычный запуск
тестов. Для тестов Qt должны быть установлены зависимости `gui`; они используют
виртуальное окно и не запускают настоящие исследования. Отдельный запуск:

```bash
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -p test_qt_gui.py -v
```

Прежние тесты Tkinter включаются отдельно в графическом сеансе:

```bash
# macOS / Linux
BENCHMARK_GUI_TESTS=1 python -m unittest discover -s tests -p test_gui.py -v
```

Windows PowerShell: сначала `$env:BENCHMARK_GUI_TESTS="1"`, затем та же команда Python.
Оконные тесты тоже используют подставной CLI и не расходуют подписку.
Живой пилот выполняется отдельно на настоящих источниках.

## Следующие этапы

Терминальные команды остаются ядром настольного интерфейса. Клиентские сборки
macOS arm64 и Windows x64 со встроенными Python, библиотеками, правилами, скиллами,
JSON-схемой и Codex CLI готовы. Следующие этапы — живой пилот Windows,
подписанные установщики и автоматическое обновление. Сейчас приложение распространяется
как `.app` в ZIP на macOS и папка с `.exe` в ZIP на Windows.

Офлайн-проверка настоящего Chromium (нужны установленный движок и разрешённый запуск
его служебных процессов; запросы к модели и внешней сети не выполняются):

```bash
BENCHMARK_BROWSER_INTEGRATION=1 QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -p test_browser_engine.py -v
```

Обработка компаний выполняется параллельно, по умолчанию два задания. Интерфейс
продолжает читать прогресс в фоне; каждый готовый результат сразу фиксируется в SQLite
одним координатором, независимо от остальных заданий. Выбор количества работников
доступен в CLI: `--workers 1` для последовательной обработки, `--workers 2` по умолчанию,
максимум 4. Повтор выбранной компании и запуск с `--token-budget` используют один поток.

При лимите подписки или ошибке авторизации новые задания не запускаются. Уже начатые
результаты сохраняются, незавершённые возвращаются в очередь для продолжения. При
нажатии «Остановить», закрытии окна или Ctrl+C запущенные запросы прерываются.
Готовые карточки сохраняются, незавершённые возвращаются в очередь и при продолжении
исследуются заново. Ожидание HTTP/DNS прерывается, процессы Codex и браузера
завершаются вместе со своими дочерними процессами. Учёт расхода токенов суммируется по
попыткам; сумма их длительностей при параллельной работе отличается от общего времени.

Для выхода из Codex CLI из терминала: `python -m benchmark logout`. В самом приложении
выход доступен верхней кнопкой после подключения. Автоматический выход при закрытии
приложения не выполняется. Для следующего входа пользователь нажимает «Войти через ChatGPT».

В версии 1.0.1 выход на macOS поддерживает системную команду Quit и ⌘Q.
Сверху показывается остаток лимита Codex по доступным периодам; подсказка содержит
время сброса. Данные запрашиваются через account/rateLimits/read раз в минуту,
без запросов к модели. При ошибке или отсутствии данных индикатор скрывается.
