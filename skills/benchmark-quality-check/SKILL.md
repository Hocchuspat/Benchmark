---
name: benchmark-quality-check
description: Проверить полноту отчёта Benchmark, принадлежность сведений нужной компании и подтверждение фактов открытыми источниками.
---

Для готового отчёта есть два результата: `completed` («Всё ок») и `needs_review`
(«Нужна проверка»). Отдельные оценки поиска сайта не определяют итоговый статус.

Проверь, что company_id совпадает с заданием и все принятые сведения относятся
к одному нужному юрлицу. Подтверди его совпавшим ИНН или минимум двумя совпавшими
реквизитами из входной карточки: юрназвание, ОГРН, адрес, телефон. Допустимы один
или несколько открытых источников любого типа. Официальный сайт необязателен.
Не переноси деятельность группы, одноимённой компании или чужого юрлица.

Для `completed` заполни с источниками `product_service_type`, `primary_activity`
и `functions_summary`. Отсутствие сайта, ОКВЭД, отдельных реквизитов/контактов,
дополнительной деятельности или недоступность неиспользованной страницы не мешают
этому статусу. Заявленный по ОКВЭД или разрешённый лицензией профиль можно описать
с явной оговоркой об основании; не выдавай его за выполненные работы.

`report_issues` — только неразрешённые проблемы, мешающие использовать сведения
в отчёте: непонятно, какой компании принадлежат функции, либо противоречивы
принятые сведения о деятельности/продуктах/функциях. Объясни конкретную проблему.
Если таких проблем нет, выдай `report_issues: []`. Пропуски основных полей Python
определит дополнительно. Разница между старым адресом и новым, исправленный контакт
Excel, неподтверждённый сайт-кандидат или другой ИНН на отвергнутом сайте сами по себе
не создают report_issues, если принятые сведения уверенно относятся к нужной компании.

В `warnings` сохраняй примечания: ограничения доступа, давность сведений, заявленный
профиль, отличия исходных контактов. Примечания не равны причинам проверки отчёта.
`missing_information` перечисляет все null-поля facts, включая дополнительные.
Не оставляй основные поля пустыми только из-за отсутствия официального сайта:
используй уже открытые сведения по ИНН или выполни целевой поиск в пределах бюджета.

Каждый заполненный факт ссылается на существующие source_ids реально прочитанных
страниц, в том числе local_web_evidence_json. Даты доступа фактические; URL и цитаты
не выдумывай. Ошибка веб-инструмента не исключает успешно прочитанную локальную копию.
Для принадлежности сайта сохраняй отдельную identity: confirmed_by_inn требует
совпавшего ИНН на самом сайте, confirmed_by_details — двух реквизитов на его домене.
Эта оценка сайта не заменяет проверку принадлежности сведений в целом.

Выдай только полный JSON установленной схемы. При недостатке сведений верни null
с конкретной причиной. Локальный валидатор проверяет структуру, источники и основные
совпадения; он не заменяет независимую проверку фактов аналитиком.
